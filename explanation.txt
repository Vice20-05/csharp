# Explanation

C# version of your Java `Id_login_hash` project, kept simple (student level).
Users are stored in a **plain text file** (`users.txt`), and **reading the file
uses exactly ONE thread** (a single background `Thread` + `Join()` in
`ReadLines()`).

## Files
- `Employee.cs` / `Manager.cs` — your Java classes, ported 1-to-1
  (in Java `extends` becomes `: base(...)` in C#).
- `PasswordHasher.cs` — Caesar cipher: `Encode` shifts letters by 3
  (`secret123` -> `vhfuhw456`), `Verify` re-encodes and compares.
- `TxtStore.cs` — the replacement for Java's `Database.java`. Reads and writes
  `users.txt`.
- `Program.cs` — menu with `try / catch / finally` and your original two
  employees at start.

## The `users.txt` format
```
id|username|passwordhash|createdat
lastid|3
1|anna|vhfuhw456|1759248000
2|bob|mtvgmt012|1759248100
```
Fields are separated by `|`. Line 1 is a header, line 2 is a counter, and
every line after that is one user.

**`lastid`** is the highest id ever handed out. SQLite generated ids with
`AUTOINCREMENT`; a text file has no such feature, so the counter is kept in
the file itself. `NextId()` returns `lastid + 1`, which means **a deleted id
is never given out again** — same behaviour as `AUTOINCREMENT`. Deleting the
last remaining user does not reset the counter.

A file written by an older version (no `lastid` line) still works: the counter
reads as 0 and the highest id already in the file is used instead, so no two
users can end up with the same id.

`createdat` is Unix seconds (UTC):
`DateTimeOffset.UtcNow.ToUnixTimeSeconds()`.

## How to run
Run it **from this folder** — `users.txt` is a relative path, so the file is
created next to wherever you start the program.
```
cd Documents/csharp
dotnet run
```

## Menu (all implemented)
| Option | What it does |
|--------|--------------|
| 1. Register | hashes the password (Caesar), saves it + a UTC timestamp + an id |
| 2. Login | checks username + password, says "Invalid credentials" on failure |
| 3. Update (GDPR) | changes the user's password hash (right to rectification) |
| 4. Delete (GDPR) | removes the user's row (right to erasure) |
| 5. Exit | quits |

## Notes
- **One thread**: `ReadLines()` starts a `Thread`, reads every line of the file
  inside it, then `Join()`s to wait — serialized on a single thread. Every
  method that touches the file goes through it.
- **Try / catch / finally**: `Main` runs the app in `try`, prints any error in
  `catch`, and always prints "Program ended." in `finally`.
- **GDPR**: users can change or delete their own data, and `users.txt` is
  gitignored (never commit personal data).
- **UNIQUE usernames**: SQLite enforced `Username UNIQUE`. `UsernameExists()`
  checks the rows by hand so the same rule applies. Registering a name twice
  prints "Username already taken" and writes nothing.
- **Usernames are case sensitive**, so `Carol` and `carol` are two different
  users. This matches SQLite's default `UNIQUE`, which also treats them as
  different.
- **Usernames are validated** by `IsValidUsername()`: not empty, and no `|`
  inside, because `|` is the field separator and would split the row.
  Passwords cannot be empty either.
- **Parsing is defensive**: `ReadAll()` skips any line without four
  `|`-separated fields, and skips the header. If the header or the counter is
  deleted or repeated by accident, no real user is lost.
- **The id counter never goes backwards**: `WriteAll()` keeps the highest value
  it has seen, so even deleting every user leaves the counter intact.
