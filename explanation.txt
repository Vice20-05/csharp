# Explanation

Fully implemented C# version of your Lab3 task, kept simple (student level).
Users are stored in a **CSV file** (`users.csv`), and **reading the file uses
exactly ONE thread** (a single background `Thread` + `Join()` in `ReadAll()`).

## Files
- `Employee.cs` / `Manager.cs` — your Java classes, ported 1-to-1
  (in Java `extends` becomes `: base(...)` in C#).
- `PasswordHasher.cs` — Caesar cipher: `Encode` shifts letters by 3
  (`secret123` -> `vhfuhw456`), `Verify` re-encodes and compares.
- `CsvStore.cs` — reads/writes `users.csv`. Each line: `username,passwordhash,createdat`.
  Reading happens on one thread in `ReadAll()`.
- `Program.cs` — menu with `try / catch / finally` and your original two employees at start.

## How to run
```
cd Documents/csharp
dotnet run
```

## Menu (all implemented)
| Option | What it does |
|--------|--------------|
| 1. Register | hashes the password (Caesar), saves it + a UTC timestamp |
| 2. Login | checks username + password, says "Invalid credentials" on failure |
| 3. Update (GDPR) | changes the user's password hash (right to rectification) |
| 4. Delete (GDPR) | removes the user's row (right to erasure) |
| 5. Exit | quits |

## Notes
- **One thread**: `CsvStore.ReadAll()` starts a `Thread`, reads every line of the
  CSV inside it, then `Join()`s to wait — serialized on a single thread.
- **Try / catch / finally**: `Main` runs the app in `try`, prints any error in
  `catch`, and always prints "Program ended." in `finally`.
- **GDPR**: users can change or delete their own data, and `users.csv` is
  gitignored (never commit personal data).
- **CSV has no UNIQUE rule** like a database — duplicate usernames are not
  prevented (could be added, but not required at this level).
- Timestamps are Unix seconds (UTC): `DateTimeOffset.UtcNow.ToUnixTimeSeconds()`.
